PURPOSE
-------
This document defines how DMF Pulse proves that its forecasts and decisions are
useful before they are trusted.

It covers:

- walk-forward testing;
- prequential evaluation;
- deadline-specific information sets;
- prevention and detection of future-data leakage;
- historical odds reconstruction;
- live-observed versus reconstructed datasets;
- nested time-series model selection;
- forecast calibration;
- proper probability scoring;
- expected-points error;
- distributional and multivariate evaluation;
- rank outcomes;
- decision regret;
- sequential transfer-policy evaluation;
- chip-value evaluation;
- price-model accuracy;
- team-value evaluation;
- ablation testing;
- benchmark design;
- statistical uncertainty;
- multiple-testing and backtest-overfitting controls;
- model confidence sets;
- promotion, rollback and trust gates.

The core scientific question is:

    IF PULSE HAD BEEN RUN AT EACH HISTORICAL FPL DEADLINE
    WITH ONLY THE INFORMATION THAT WAS GENUINELY AVAILABLE THEN,
    WHAT WOULD IT HAVE FORECAST, RECOMMENDED AND ACHIEVED?

A backtest that cannot answer that question is not evidence.

GOVERNING PRINCIPLE
-------------------
Pulse maintains four distinct evaluation layers.

LAYER 1 — FORECAST QUALITY

Did the system predict:

- minutes;
- starts;
- goals;
- points;
- prices;
- ownership;
- rank;

accurately and honestly?

LAYER 2 — DISTRIBUTION QUALITY

Were:

- probabilities calibrated;
- tails credible;
- prediction intervals correct;
- correlations and joint scenarios realistic?

LAYER 3 — DECISION QUALITY

Did the forecasts lead to better:

- transfers;
- lineups;
- captaincy;
- chip timing;
- rank-target decisions;

after costs and opportunity costs?

LAYER 4 — OPERATIONAL FIDELITY

Could the recommendation actually have been produced:

- before the deadline;
- from the available data;
- under the active rules;
- within runtime;
- without hindsight or hidden corrections?

A model may improve one layer and worsen another.

No single headline metric is sufficient.

CRITICAL TEMPORAL PRINCIPLE
---------------------------
The strict live backtest uses:

    usable_at <= historical information cutoff

not:

- source timestamp alone;
- current database state;
- final corrected data;
- today's player mappings;
- closing odds;
- postdeadline lineups;
- future fixture assignments;
- future model weights.

Historical evaluation labels may use final corrected outcomes.

Historical training features and model states may use only the data versions
known at that historical refit time.

NORMATIVE LANGUAGE
------------------
MUST / MUST NOT:
A non-negotiable requirement.

SHOULD / SHOULD NOT:
The default. Deviations require a documented research decision.

MAY:
Optional, provided no MUST requirement is violated.

======================================================================
0. EXECUTIVE EVALUATION DECISIONS
======================================================================

0.1 SELECTED PRIMARY DESIGN
---------------------------
The production evaluation design is:

    NESTED WALK-FORWARD / ROLLING-ORIGIN EVALUATION
    + IMMUTABLE DEADLINE INFORMATION BUNDLES
    + PREQUENTIAL FORECAST LOGGING
    + OUT-OF-SAMPLE POLICY REPLAY
    + UNTOUCHED FINAL HOLDOUTS
    + PROPER SCORING AND DECISION REGRET
    + MULTIPLE-TESTING CONTROLS.

0.2 WALK-FORWARD UNIT
---------------------
The normal outer evaluation step is one FPL deadline.

For deadline d:

1. select all training information usable before the model-refit cutoff;
2. select hyperparameters/policies only from earlier inner folds;
3. fit/calibrate using earlier data;
4. freeze every model, mapping, rule and policy version;
5. build the historical deadline bundle;
6. issue projections and decisions;
7. store them before revealing future outcomes;
8. advance time;
9. evaluate against official final outcomes;
10. repeat.

0.3 EXPANDING VERSUS ROLLING WINDOW
----------------------------------
Primary:

- expanding history with parameter-specific recency and regime weighting.

Challenger:

- fixed rolling windows;
- season-weighted windows;
- hierarchical dynamic models.

The window is selected within the inner walk-forward process.

No test-period outcome may choose it.

0.4 NESTED MODEL SELECTION
--------------------------
Outer folds estimate real out-of-sample performance.

Inner rolling-origin folds choose:

- hyperparameters;
- features;
- calibration;
- ensemble weights;
- robust-policy parameters;
- optimisation horizon;
- confidence thresholds.

Using the same outer outcomes for tuning and reporting is prohibited.

0.5 FINAL HOLDOUT
-----------------
At least one complete season or a substantial final contiguous block is a
locked confirmatory holdout when historical depth permits.

Once opened for confirmatory testing:

- result is recorded;
- repeated tuning against it is prohibited;
- subsequent changes require a new holdout or prospective evidence.

0.6 PROSPECTIVE STANDARD
------------------------
The strongest evidence is:

    LIVE_OPERATIONAL forecasts and decisions generated before real deadlines.

Retrospective reconstructed tests are useful but cannot substitute for
prospective validation where source history is incomplete.

0.7 DATASET MODES
-----------------
Every result is labelled:

LIVE_OBSERVED:
The live system genuinely had and could use the information.

RAW_OBSERVED:
Data arrived before the deadline but were not operationally usable then.

RECONSTRUCTED:
Data or mappings were obtained later.

FINAL_OUTCOME:
Corrected labels.

COUNTERFACTUAL:
A deliberately unavailable/hindsight scenario.

Only LIVE_OBSERVED supports a claim about actual live operational performance.

0.8 PRIMARY PROJECTION METRICS
------------------------------
For point forecasts:

- MAE;
- RMSE;
- bias.

For probabilities:

- logarithmic score/log loss;
- Brier score;
- calibration intercept/slope;
- reproducible reliability diagrams.

For complete univariate distributions:

- ranked probability score or discrete CRPS;
- logarithmic score of the observed outcome;
- randomized PIT/rank histograms;
- interval coverage and width.

For joint/multivariate distributions:

- energy score;
- variogram score;
- covariance and joint-threshold calibration.

0.9 PRIMARY DECISION METRICS
----------------------------
- cumulative points above baseline;
- net transfer value;
- points lost to hits;
- hit-adjusted points gained;
- captaincy incremental points;
- autosub/bench value;
- chip incremental policy value;
- team-value gain and points enabled by budget;
- rank-target probability calibration;
- realised policy regret;
- forced-transfer rate;
- action stability;
- solver and operational success.

0.10 PROMOTION PRINCIPLE
------------------------
A model/policy is promoted only if it:

- improves a predeclared primary metric or decision utility;
- remains calibrated;
- does not create material subgroup failure;
- passes leakage/reproducibility tests;
- improves or does not materially harm downstream decisions;
- survives multiple-testing controls;
- passes prospective or locked-holdout evidence;
- has a rollback path.

0.11 PERFECT HINDSIGHT
----------------------
Perfect hindsight is an unattainable upper bound.

It is useful for:

- measuring remaining headroom;
- diagnosing optimiser limitations;
- separating forecast error from optimisation error.

It MUST NOT be presented as a feasible benchmark or used to tune against the
test outcome.

======================================================================
1. DEFINITIONS
======================================================================

1.1 FORECAST ORIGIN
-------------------
The historical instant at which a forecast or decision is made.

For FPL decisions:
the official Gameweek deadline, or an earlier explicitly logged transfer-timing
decision.

1.2 INFORMATION CUTOFF
----------------------
The latest allowed `usable_at` instant for features.

1.3 LABEL CUTOFF
----------------
The latest outcome finality version used for evaluation.

Labels can be final and corrected after the event.

1.4 TRAINING CUTOFF
-------------------
The latest fact/outcome version available to the model-fitting process at the
historical refit time.

1.5 VINTAGE
-----------
The version of a fact/dataset as it existed at a particular system time.

1.6 FOLD
--------
One contiguous historical evaluation period.

1.7 OUTER FOLD
--------------
Untouched forecast/policy evaluation.

1.8 INNER FOLD
--------------
Model, feature and policy selection using only data before the outer test.

1.9 PREQUENTIAL EVALUATION
--------------------------
Sequentially:

- predict first;
- reveal outcome;
- score;
- update.

Dawid's prequential principle assesses models by the sequence of their
predictions for future observations.

1.10 POLICY
-----------
A mapping from information state to action.

1.11 DECISION REGRET
--------------------
Utility loss relative to a comparator under the same realised or simulated
state.

1.12 ORACLE
-----------
A comparator using information unavailable at the decision time.

Always labelled unattainable.

1.13 BENCHMARK
--------------
A completely specified reproducible forecasting or decision method.

1.14 ABLATION
-------------
A controlled removal/replacement of one module or feature group.

1.15 CALIBRATION
----------------
Forecast probabilities/distributions match observed conditional frequencies or
distributional behaviour.

1.16 SHARPNESS
--------------
Concentration of a probabilistic forecast, subject to calibration.

3. EVALUATION DATASET MODES
======================================================================

3.1 STRICT LIVE DATASET
-----------------------
Features:
LIVE_OPERATIONAL only.

Training:
uses historical training vintages known by each refit date.

Evaluation:
FINAL_OUTCOME labels.

Purpose:
claim about what Pulse could genuinely have done.

3.2 RAW-OBSERVED COUNTERFACTUAL
-------------------------------
Includes data received before deadline but processed/mapped later.

Purpose:
quantify operational latency cost.

Not live performance.

3.3 RECONSTRUCTED RESEARCH DATASET
----------------------------------
Includes retrospectively downloaded:

- odds;
- events;
- injuries;
- mappings;
- lineups.

Purpose:
algorithm development and long-history comparison.

Limitations displayed.

3.4 CURRENT-VINTAGE RETROSPECTIVE DATASET
-----------------------------------------
Uses today's corrected canonical history.

Allowed for:

- football-model research;
- final-label analysis;
- nonlive benchmarks.

Prohibited for live-performance claims.

3.5 PERFECT-INFORMATION DATASET
-------------------------------
May include:

- actual lineups;
- actual minutes;
- future prices;
- fixture outcomes;
- best transfers.

Purpose:
upper bounds and error decomposition.

3.6 NO MODE MIXING
------------------
A report cannot average strict-live and reconstructed folds without separate
results.

======================================================================
4. WALK-FORWARD EVALUATION DESIGN
======================================================================

4.1 ROLLING FORECAST ORIGIN
---------------------------
Time-series cross-validation evaluates each future origin using only prior
observations.

For deadline d:

    Training_d = all permitted observations with usable/training availability
                 before cutoff_d

    Test_d = outcomes after deadline d.

4.2 EXPANDING WINDOW
--------------------
Start with minimum training period.

Add each completed/refit-eligible Gameweek.

4.3 ROLLING WINDOW
------------------
Use only most recent W periods.

W selected in inner folds.

4.4 MULTI-HORIZON
-----------------
Evaluate separately:

- current Gameweek;
- 2-Gameweek;
- 3-Gameweek;
- 5-Gameweek;
- optimisation horizon;
- remaining season where relevant.

A model can be strong at one horizon and weak at another.

4.5 REFIT CADENCE
-----------------
Replay actual production cadence:

- weekly;
- after each fixture;
- monthly;
- online filtering.

Do not refit retrospectively more often than production would have.

4.6 MODEL FREEZE
----------------
Before scoring outer fold, store:

- feature schema;
- training dataset version;
- parameters;
- calibration;
- ensemble weights;
- code;
- random seed;
- rules;
- source bundle.

4.7 OUTCOME REVEAL
------------------
Only after immutable forecast publication.

4.8 PREQUENTIAL LOG
-------------------
Each forecast receives:

- issue time;
- cutoff;
- model;
- distribution;
- later score;
- correction label.

4.9 SEASON TRANSITION
---------------------
Historical season-to-season evaluation must reproduce:

- newly promoted teams;
- transfers;
- new players;
- new managers;
- rules changes;
- preseason uncertainty.

4.10 FIRST-SEASON COLD START
---------------------------
Predeclared priors and historical inputs.
Do not use later target-season data to revise GW1 evaluation.

======================================================================
5. NESTED WALK-FORWARD MODEL SELECTION
======================================================================

5.1 OUTER LOOP
--------------
Measures the full modelling procedure, including:

- feature selection;
- hyperparameter tuning;
- calibration;
- ensemble construction;
- policy tuning.

5.2 INNER LOOP
--------------
Earlier rolling origins select configuration.

5.3 SEARCH BUDGET
-----------------
Every experiment records:

- number of models;
- hyperparameter configurations;
- feature variants;
- policy variants;
- seeds;
- metrics inspected.

5.4 NO FLAT REPORTING
---------------------
If a configuration is selected by its performance on a fold, that same fold is
not an unbiased performance estimate.

5.5 COMPUTATIONAL SHORTCUT
--------------------------
Where full nesting is infeasible:

- locked validation period for tuning;
- later untouched test;
- clear limitation;
- prospective confirmation.

5.6 ENSEMBLE WEIGHTS
--------------------
Learned only from inner/pre-outer data.

5.7 CALIBRATION MODEL
---------------------
Fit only on past forecasts/outcomes.

5.8 THRESHOLDS AND CONFIDENCE GRADES
------------------------------------
Promotion/alert/action thresholds are hyperparameters and must be tuned inside
training/validation, not on the final test.

7.4 LINEUP LEAKAGE
------------------
Official/postdeadline lineups used in predeadline model.

7.5 CLOSING-ODDS LEAKAGE
------------------------
Kickoff/closing market used for an earlier FPL deadline.

7.6 FIXTURE-ASSIGNMENT LEAKAGE
------------------------------
Final Double/Blank Gameweek assignment used before announcement.

7.7 ENTITY-RESOLUTION LEAKAGE
-----------------------------
A mapping fixed later applied to live historical features.

7.8 PREPROCESSING LEAKAGE
-------------------------
Scaling, imputation, feature selection or embeddings fitted on test data.

7.9 TARGET ENCODING LEAKAGE
---------------------------
Player/team aggregates include test outcomes.

7.10 HYPERPARAMETER LEAKAGE
---------------------------
Test performance chooses settings.

7.11 CALIBRATION LEAKAGE
------------------------
Calibration curve fitted using evaluation outcomes.

7.12 ENSEMBLE-WEIGHT LEAKAGE
----------------------------
Future model scores choose historical weights.

7.13 OPTIMISER LEAKAGE
----------------------
Future scenario path actions know unrevealed events.

7.14 SURVIVORSHIP LEAKAGE
-------------------------
Only players/managers who remain in final data are included.

7.15 SAMPLE-SELECTION LEAKAGE
-----------------------------
Final top managers define a live "elite" cohort.

7.16 RULE LEAKAGE
-----------------
Later-season rule interpretation used before publication.

7.17 RETROSPECTIVE MANUAL LEAKAGE
---------------------------------
Analyst remembers later news/result when coding history.

7.18 LABEL-REVISION LEAKAGE
---------------------------
Final corrected outcome used to train a model before that correction existed.

7.19 LEAKAGE TESTS
------------------
Automated canaries:

- insert postcutoff extreme value;
- confirm output unchanged;
- shift usable_at;
- remove current mapping;
- compare current versus as-of queries;
- fail build if unrestricted latest view appears.

8. HISTORICAL ODDS RECONSTRUCTION
======================================================================

8.1 PURPOSE
-----------
Build market baselines and historical Pulse variants without claiming data were
available when they were not.

8.2 EVIDENCE HIERARCHY
----------------------
1. Pulse's own immutable predeadline snapshots.
2. Time-stamped historical exchange/API observations with rights.
3. Time-stamped manual observations.
4. Opening/closing fixed-odds records with known semantics.
5. Untimed match-level odds.
6. No market.

8.3 BETFAIR HISTORICAL DATA
---------------------------
Betfair's historical service provides time-stamped Exchange data; official
documentation says historical files are available from May 2015 and identifies
JSON archive formats.

Use:

- market/selection mapping;
- market status;
- time;
- last traded/best prices where tier provides them;
- traded volume where provided;
- in-play flag.

8.4 BETFAIR BASIC LIMITATION
----------------------------
The free BASIC tier/source fields and snapshot cadence may not reproduce a full
predeadline order book.

Store tier and field completeness.

8.5 FOOTBALL-DATA.CO.UK
-----------------------
Provides free historical results and fixed-odds CSVs across many seasons.

Use for:

- broad 1X2/totals/handicap benchmark;
- bookmaker/market-history research.

Limitations:

- many columns are closing or summary prices;
- time-varying deadline snapshots generally absent;
- bookmaker coverage changes by season;
- not player-prop history;
- not proof of what Pulse knew at FPL deadline.

8.6 DEADLINE ALIGNMENT
----------------------
For time-stamped quotes:

    select latest usable quote with observed_at <= historical FPL deadline.

Never use:

- nearest quote in absolute time;
- first quote after deadline;
- kickoff close.

8.7 QUOTE AGE
-------------
Record age at deadline and apply DMFP-06 freshness policy.

8.8 NO PREDEADLINE QUOTE
------------------------
Set:

    NO_MARKET_AT_DEADLINE

Do not backfill from later opening.

8.9 UNTYPED ODDS
----------------
If only an untimed closing price exists:

- dataset mode RECONSTRUCTED_CLOSING;
- use as market-strength research/oracle-like benchmark;
- never as strict deadline benchmark.

8.10 PLAYER PROPS
-----------------
No complete reliable free historical EPL player-prop dataset was identified in
DMFP-04.

Therefore:

- historical player-prop Pulse tests are incomplete/reconstructed;
- collect prospectively from 2026/27;
- market-only/player-prop claims must identify coverage;
- no market = missing, not zero.

8.11 ODDS NORMALISATION VERSION
-------------------------------
Reconstruct raw quotes first.
Apply historical/current DMFP-06 method under a versioned experiment.

Distinguish:

- original live normalisation;
- current research re-normalisation.

8.12 ODDS DATASET GRADE
-----------------------

exact predeadline live snapshot.

B:
time-stamped historical observation close to deadline.

C:
time-stamped but sparse/delayed/incomplete.

D:

10. BENCHMARK SUITE
======================================================================

10.1 BENCHMARK PRINCIPLES
-------------------------
Every benchmark:

- uses the same information cutoff;
- uses the same player universe;
- follows the same target rules;
- has fixed documented parameters;
- produces the required distribution where applicable;
- is evaluated at the same horizons.

10.2 B0 — NAIVE RECENT-POINTS MODEL
-----------------------------------
Purpose:
Simple recency benchmark.

Player expected points per fixture/Gameweek from:

- exponentially weighted recent official FPL points;
- explicit appearance/minutes denominator;
- position/team fallback for sparse players;
- no market;
- no opponent model beyond optional simple fixture adjustment in a separate
  variant.

Required fixed variants:

B0A:
last 3 appearances average.

B0B:
last 5 appearances average.

B0C:
EWMA selected in inner folds.

Distribution:

- empirical/hierarchical residual distribution;
- zero/appearance mixture if benchmark specification includes it.

No future appearances used.

10.3 B1 — OFFICIAL FPL-FORM BASELINE
------------------------------------
Use the official form field captured at the deadline.

Official help/reference says form is average points per match over matches played
by the player's club in the previous 30 days.

Faithful baseline:

    expected fixture points = historical deadline FPL form

with explicit:

- Blank/Doubles;
- availability;
- no reinterpretation.

A second FPL-form-plus-minutes variant may exist but must not replace the faithful
baseline.

10.4 B2 — MARKET-ONLY MODEL
---------------------------
Inputs:

- predeadline team markets;
- available player markets;
- generic league/position priors;
- no Pulse player-history ability model;
- no bespoke minutes model.

For missing player props:

- allocate team goals with generic position/price/market-listing shares;
- mark coverage.

Purpose:
measure the information in betting markets alone.

10.5 B3 — MARKET PLUS MINUTES MODEL
-----------------------------------
Inputs:

- DMFP-06 markets;
- DMFP-07 coherent start/minutes distributions;
- generic event allocation;
- no full historical player-event engine.

Purpose:
measure incremental value of minutes and lineup modelling.

10.6 B4 — COMPLETE PULSE MODEL
------------------------------
All accepted modules:

- markets;
- minutes;
- events;
- scoring;
- uncertainty;
- price;
- optimiser;
- chips/rank as objective requires.

10.7 B5 — PERFECT-HINDSIGHT UPPER BOUND
---------------------------------------
Variants must be separate.

B5A PERFECT LINEUP/MINUTES:
actual starters/minutes, predeadline event distribution.

B5B PERFECT FOOTBALL OUTCOMES:
actual player points, best legal current tactical action.

B5C PERFECT GAMEWEEK TRANSFERS:
actual points/prices and best legal transfers under historical state.

B5D PERFECT SEASON POLICY:
clairvoyant dynamic optimisation with all future outcomes.

These are upper bounds, not comparable feasible models.

10.8 ADDITIONAL DECISION BENCHMARKS
-----------------------------------
- no transfer;
- one-Gameweek greedy;
- five-Gameweek deterministic;
- public FPL form;
- no chip until expiry;
- simple largest-DGW chip rules;
- pure expected points;
- template/rank heuristics.

======================================================================
11. POINT FORECAST METRICS
======================================================================

11.1 MAE
--------
    MAE = mean |y - y_hat|

Appropriate for median-like point forecasts under absolute loss.

11.2 RMSE
---------
    RMSE = sqrt(mean (y - y_hat)^2)

Penalises larger errors and targets the conditional mean under squared loss.

11.3 BIAS
---------
    Bias = mean(y_hat - y)

Report signed and absolute calibration-in-the-large.

11.4 MEDIAN ERROR
-----------------
If reporting median points, evaluate median absolute loss/pinball loss.

11.5 MEAN VERSUS MEDIAN
-----------------------
Do not evaluate a median forecast as if it claimed to be the mean.

Gneiting's point-forecast research emphasises that the loss function determines
the optimal target functional.

11.6 WEIGHTED METRICS
---------------------
Report:

- all player rows;
- equal Gameweek;
- equal fixture;
- candidate/owned player;
- high expected-points player;
- price/position.

Avoid letting inactive low-value players dominate.

11.7 OUTCOME-CONDITIONED BIAS
-----------------------------
Do not make primary claims from only:

- players who scored;
- top scorers;
- selected by hindsight.

Predeclare subsets.

11.8 MULTI-GAMEWEEK
-------------------
Score accumulated player points at exact horizon.

======================================================================
12. PROBABILITY SCORING
======================================================================

12.1 LOGARITHMIC SCORE
----------------------
For binary event y and probability p:

    LogLoss = -[y log p + (1-y) log(1-p)]

Strongly penalises confident wrong forecasts.

Use numerical floors only for computation, not to disguise invalid zero/one
probabilities.

12.2 BRIER SCORE
----------------
    BS = mean (p-y)^2

Interpretable and bounded for binary events.

12.3 EVENTS
-----------
- start;
- appearance;
- 60+;
- zero minutes;
- goal;
- assist;
- clean sheet;
- 5+/10+/15+ points;
- price rise/fall;
- chip/target events.

12.4 MULTICLASS LOG/BRIER
-------------------------
For START/BENCH/OUT, score complete probability vector.

12.5 RANKED PROBABILITY SCORE
----------------------------
For ordered/discrete outcomes:

- minutes;
- goals;
- FPL points;
- prices;
- rank bands.

Equivalent CRPS-like cumulative comparison.

12.6 PROPER SCORING
-------------------
Gneiting and Raftery show that strictly proper scoring rules encourage honest
predictive distributions.

Primary model selection must use proper scores.

12.7 RARE EVENTS
----------------
Report:

- log score;
- Brier;
- precision-recall diagnostics;
- calibration.

Do not use accuracy.

======================================================================
13. CALIBRATION EVALUATION
======================================================================

13.1 RELIABILITY
----------------
A 30% event should occur approximately 30% among comparable forecasts.

13.2 CORP RELIABILITY DIAGRAM
-----------------------------
Use Consistent, Optimally binned and Reproducible reliability diagrams based on
isotonic regression where appropriate.

This avoids arbitrary hand-selected bins.

13.3 CALIBRATION INTERCEPT/SLOPE
--------------------------------
Binary logistic calibration:

    logit(P(Y=1))
      =
      a + b logit(p)

Ideal:

    a = 0
    b = 1.

13.4 ECE
--------
Expected calibration error may be reported, but:

- depends on bins;
- can hide local failure;
- is not a proper score;
- never primary alone.

13.5 BRIER DECOMPOSITION
------------------------
Report calibration/reliability, discrimination/resolution and uncertainty using
a statistically principled decomposition.

13.6 SUBGROUP CALIBRATION
-------------------------
- position;
- team;
- price;
- ownership;
- early/middle/late;
- new manager;
- injury return;
- source confidence;
- market coverage;
- lead time.

13.7 SAMPLE SIZE
----------------
Show confidence bands/counts.
Do not declare calibration from ten events.

13.8 RECALIBRATION
------------------
Evaluate raw and recalibrated forecasts separately.

A recalibrator is trained only on prior folds.

======================================================================
14. DISTRIBUTION AND INTERVAL EVALUATION
======================================================================

14.1 DISCRETE POINTS/MINUTES
----------------------------
Use:

- ranked probability score/discrete CRPS;
- log probability of realised value;
- randomized PIT;
- quantile coverage.

14.2 RANDOMIZED PIT
-------------------
For discrete outcome, randomize within the probability mass at the observed
value.

Avoid using continuous PIT naively.

14.3 PREDICTION INTERVAL COVERAGE
---------------------------------
For nominal interval alpha:

    empirical coverage
    versus
    alpha.

14.4 WIDTH/SHARPNESS
--------------------
Coverage without width rewards vacuous intervals.

Report:

- average width;
- median width;
- interval score;
- conditional width.

14.5 CENTRAL AND ONE-SIDED
--------------------------
Evaluate:

- central 50/80/90/95%;
- upper-tail 90/95%;
- lower-tail.

14.6 CONDITIONAL COVERAGE
-------------------------
Coverage by:

- forecast mean;
- uncertainty grade;
- player type;
- Gameweek stage.

14.7 QUANTILE LOSS
------------------
Pinball loss for selected quantiles.

14.8 EXTREMES
----------------
10+/15+ FPL points and rare rank targets require dedicated threshold metrics and
enough samples; average CRPS can be insensitive to extreme-tail quality.

15.7 COPULA/RANK HISTOGRAM

17. DECISION BACKTEST ARCHITECTURE
======================================================================

17.1 POLICY REPLAY
------------------
At every deadline:

1. restore historical manager state;
2. load historical information bundle;
3. generate forecasts;
4. solve decision;
5. execute only allowed current action;
6. update state from actual price/outcome;
7. continue.

17.2 NO RETROSPECTIVE RECOMMENDATION
------------------------------------
Do not generate the whole season's action list with future outcomes available.

17.3 POLICY VERSION
-------------------
Freeze policy throughout confirmatory test unless the test specifically
evaluates online updates.

17.4 REAL MANAGER START
-----------------------
Possible starts:

- Sebastian's historical squad/state;
- synthetic legal GW1 squad;
- benchmark squad;
- multiple random/strong initial states.

17.5 STATE DEPENDENCE
--------------------
One poor early action changes later feasible decisions.
Sequential evaluation preserves it.

17.6 PRICE/TRANSFER STATE
------------------------
Use historical price and manager purchase/selling values.

17.7 OPERATIONAL FAILURE
------------------------
Include:

- missing data;
- solver timeout;
- source outage;
- fallback action.

An idealised backtest and operational backtest are separate.

======================================================================
18. DECISION REGRET
======================================================================

18.1 EX-ANTE MODEL REGRET
-------------------------
Under model/scenario world:

    Regret_model(a)
      =
      best predicted feasible utility
      - predicted utility(a).

Used for robust policy diagnostics.

18.2 EX-POST REALISED REGRET
----------------------------
For realised future path over horizon H:

    Regret_realised(a)
      =
      utility(best legal action at historical decision time,
              evaluated on realised path)
      - utility(a on realised path).

The comparator can know the future path for evaluation but not alter historical
legality.

Label as hindsight regret.

18.3 POLICY REGRET
------------------
Compare complete sequential policies over a season.

18.4 DECISION-FOCUSED LOSS
--------------------------
Predict-then-optimise research defines losses based on the downstream decision
error rather than only coefficient prediction error.

Pulse uses decision regret for evaluation and possible future training, but
keeps forecast calibration as an independent requirement.

18.5 ORACLE LEVELS
------------------
- perfect current Gameweek outcome;
- perfect H-Gameweek path;
- perfect full season;
- perfect information with legal transitions.

18.6 NORMALIZED REGRET
----------------------
    normalized regret
      =
      regret / max(|oracle utility - baseline utility|, epsilon)

Use alongside absolute points.

18.7 REGRET DISTRIBUTION
------------------------
Report:

- mean;
- median;
- p90/p95;
- maximum;
- by decision type;
- by confidence.

18.8 NO SINGLE-OUTCOME OVERINTERPRETATION
----------------------------------------
A correct high-probability decision can have high realised regret through bad
luck.

Evaluate across many decisions and proper forecasts.

19.5 REVERSALS

25. STATISTICAL UNCERTAINTY
======================================================================

25.1 BLOCK BOOTSTRAP
--------------------
Resample at appropriate clusters:

- Gameweek;
- fixture;
- season;
- manager trajectory.

Preserve within-match/player dependence.

25.2 PLAYER CLUSTER
-------------------
For player-level repeated rows, use multiway or player-block sensitivity where
needed.

25.3 GAMEWEEK AS PRIMARY POLICY BLOCK
-------------------------------------
Sequential decision points are strongly correlated within a Gameweek.

25.4 CONFIDENCE INTERVALS
------------------------
For metric differences:

- block bootstrap;
- paired scenario bootstrap;
- season-level variation;
- Bayesian posterior where appropriate.

25.5 PAIRED COMPARISON
----------------------
Models evaluated on same outcomes.
Use paired loss differences.

25.6 DIEBOLD–MARIANO
--------------------
Can compare forecast loss sequences.

Diebold emphasises that the DM test compares forecasts, not abstract models, and
its assumptions/serial dependence must be respected.

Use cautiously with:

- overlapping horizons;
- small samples;
- nested models;
- Gameweek clusters.

25.7 MODEL CONFIDENCE SET
-------------------------
Hansen, Lunde and Nason's Model Confidence Set returns a set that can contain the
best forecasting method at a chosen confidence level.

Use to avoid declaring a single winner when data are uninformative.

25.8 EFFECT SIZE
----------------
Statistical significance without material decision value is insufficient.

Report:

- absolute score change;
- relative skill;
- points;
- regret;
- target probability.

33. TESTING THE EVALUATION SYSTEM

33.1 SYNTHETIC CALIBRATED FORECASTS

33.2 DELIBERATE MISCALIBRATION

33.3 LEAKAGE CANARY
-------------------
