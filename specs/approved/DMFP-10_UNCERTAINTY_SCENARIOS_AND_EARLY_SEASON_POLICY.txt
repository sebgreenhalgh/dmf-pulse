PURPOSE
-------
This document defines how DMF Pulse reasons and acts when the future is
uncertain.

It distinguishes and operationalises:

- aleatoric uncertainty;
- epistemic uncertainty;
- market uncertainty;
- model uncertainty;
- lineup uncertainty;
- data-source uncertainty;
- rule uncertainty;
- structural/regime uncertainty;
- operational uncertainty;
- strategic/rank uncertainty.

It decides how Pulse uses:

- Bayesian priors;
- hierarchical shrinkage;
- partial pooling;
- sequential posterior updating;
- model ensembles;
- posterior predictive distributions;
- scenario trees;
- rolling-horizon optimisation;
- robust optimisation;
- robust regret;
- conditional value at risk;
- distributionally robust optimisation;
- sensitivity analysis;
- value of information;
- value of waiting;
- flexibility and option value;
- team value as an instrumental state variable.

The practical question is:

    HOW SHOULD PULSE BEHAVE DIFFERENTLY IN GAMEWEEK 2
    COMPARED WITH GAMEWEEK 30?

The answer is not merely:

    "be more conservative early."

Pulse must specify:

- which beliefs receive more shrinkage;
- which observations update quickly;
- which uncertainty is reducible;
- which actions preserve future choices;
- when waiting has value;
- when team-value appreciation is worth pursuing;
- which risks should be penalised;
- when robustness becomes excessive caution;
- how later rank objectives can legitimately change action utility.

GOVERNING PRINCIPLE
-------------------
Pulse will maximise expected season decision value while preserving the ability
to react to information.

It will not confuse:

- outcome randomness with ignorance;
- low confidence with low expected points;
- high variance with a bad player;
- team value with FPL points;
- one surprising match with a new permanent regime;
- waiting with indecision;
- worst-case optimisation with good robustness.

The selected decision philosophy is:

    BAYESIAN FOR BELIEFS
    + SCENARIO-BASED FOR DEPENDENCE
    + ROLLING-HORIZON FOR ADAPTATION
    + ROBUSTNESS FOR MODEL/STRUCTURAL ERROR
    + VALUE OF INFORMATION FOR TIMING
    + EXPECTED SEASON POINTS AS THE PRIMARY ECONOMIC OBJECTIVE

IMPORTANT TAXONOMY CAUTION
--------------------------
The aleatoric/epistemic distinction is useful but not sufficient by itself.

Recent methodological work has highlighted that these labels can become
incoherent when they are asked to represent all sources of predictive
uncertainty.

Pulse therefore uses them as a top-level explanation and maintains a more
specific operational uncertainty ledger:

- football-event randomness;
- latent-state uncertainty;
- parameter uncertainty;
- model-class uncertainty;
- regime uncertainty;
- market disagreement;
- source/measurement uncertainty;
- rules uncertainty;
- optimisation uncertainty.

NORMATIVE LANGUAGE
------------------
MUST / MUST NOT:
A non-negotiable requirement.

SHOULD / SHOULD NOT:
The default. Deviations require a documented architecture decision.

MAY:
Optional, provided no MUST requirement is violated.

======================================================================
0. EXECUTIVE DECISION POLICY
======================================================================

0.1 PRIMARY OBJECTIVE
---------------------
Pulse's default objective is not weekly rank and not immediate team value.

It is:

    maximise expected cumulative FPL points over the remaining season,
    subject to legal state transitions,
    with a rolling-horizon approximation to future adaptation.

A practical optimisation objective at deadline t is:

    maximise over action a:

        E[ points_t:t+H(a, omega) ]
      + E[ terminal_value(S_t+H) ]
      - transfer_hit_cost(a)
      - epistemic_regret_penalty(a)
      - irreversibility_penalty(a)
      - operational_risk_penalty(a)

where:

- omega is a coherent future scenario;
- H is the explicit optimisation horizon;
- terminal_value approximates value beyond H;
- terminal state includes squad, bank, free transfers, chips, price positions,
  fixtures, information and flexibility.

Rank-specific utility is introduced later by DMFP-14, not silently mixed into
the default points objective.

0.2 ROBUSTNESS TARGET
---------------------
Pulse will not impose a generic penalty on all points variance.

Ordinary football variance is aleatoric:

- goals;
- cards;
- bonus ties;
- random results.

Penalising it indiscriminately can remove legitimate upside without improving
expected season points.

The robustness overlay primarily targets:

- model-family disagreement;
- structural/regime uncertainty;
- source/data failure;
- lineup/availability uncertainty;
- rules ambiguity;
- severe regret under plausible worlds;
- irreversible commitments;
- forced-future-transfer risk.

0.3 SELECTED PRODUCTION DECISION SCORE
--------------------------------------
Initial production comparison:

    decision_score(a)
      =
        posterior_expected_utility(a)
      - lambda_regret x robust_regret(a)
      - lambda_lockin x lock_in_cost(a)
      - lambda_operational x operational_failure_cost(a)
      + flexibility_value(a)
      + information_timing_value(a)

The optimiser MUST also report separately:

- pure expected-points optimum;
- robust-policy optimum;
- highest-flexibility alternative;
- team-value-sensitive alternative;
- sensitivity breakpoints.

No opaque weighted score may replace the decomposed evidence.

0.4 ROBUST REGRET
-----------------
For epistemic/model world m:

    regret(a,m)
      =
      max_b E[U(b) | m] - E[U(a) | m]

Selected initial robust regret:

- weighted 90th percentile of regret across plausible model/regime worlds;
- maximum regret shown as a diagnostic;
- worst-case action not automatically selected.

This protects against choosing an action whose apparent superiority exists only
under one fragile model.

0.5 TEAM VALUE
--------------
Team value is an instrument for future points, not an independent prize.

Pulse assigns no fixed universal value such as:

    £0.1m = 0.5 points.

Instead it estimates the marginal point value of money by counterfactual
re-optimisation:

    MV_budget(£0.1m)
      =
      expected optimal future points with £0.1m extra usable budget
      -
      expected optimal future points without it.

This marginal value depends on:

- season stage;
- current price structure;
- target players;
- price brackets;
- free transfers;
- squad flexibility;
- chip plan;
- fixture horizon.

0.6 EARLY-SEASON TEAM-VALUE POLICY
----------------------------------
Early price appreciation can be more valuable than late appreciation because:

- it can expand the feasible squad for more future deadlines;
- more transfers remain to exploit the added budget;
- price tiers can otherwise block future moves.

But price chasing is not a standalone objective.

A price-motivated transfer is allowed only if:

    expected football points gain/loss
    + marginal future budget value
    + future route/flexibility value
    - hit cost
    - information sacrificed by acting early
    - reversal/lock-in risk

is positive under the robust scenario set.

REFERENCE-ONLY official price mechanics create an important asymmetry:

- a price fall is fully reflected in selling value;
- only half of a price rise is retained on sale, rounded down.

Therefore avoiding a likely fall can have more immediate budget value than
chasing one isolated £0.1m rise.

Target-season rules must be verified.

0.7 GAMEWEEK 2 POLICY
---------------------
Typical Gameweek 2 behaviour:

- strong historical/market priors;
- substantial hierarchical shrinkage;
- wide epistemic and structural intervals;
- rapid update for role, lineup and set-piece information;
- slow update for stable ability from one match;
- explicit new-manager/new-signing/promoted-team scenarios;
- robust-regret and flexibility emphasis;
- high value of rolling a transfer where the squad is healthy;
- high value of banked cash and multiple transfer routes;
- team-value protection considered, but not at any points cost;
- fewer long-term irreversible commitments;
- hits require unusually strong evidence;
- captaincy remains based on expected distribution, not fear of variance;
- model-confidence grade prominently affects recommendation strength.

0.8 GAMEWEEK 30 POLICY
----------------------
Typical Gameweek 30 behaviour:

- lower parameter uncertainty for established teams/players;
- less shrinkage toward preseason priors;
- greater weight on current-season role and market evidence;
- shorter runway for team-value appreciation;
- marginal budget value driven by specific affordability bottlenecks;
- flexibility focused on blanks, doubles, chips and fixture rescheduling;
- remaining free transfers/chips have high time-specific value;
- irreversible long-term price structure matters less;
- rank utility may justify controlled upside/differentiation through DMFP-14;
- robust penalty decreases for well-identified football parameters but may rise
  for schedule, injury or new-manager shocks;
- waiting value depends on imminent team news and price/fixture risk, not season
  number alone.

0.9 STATE-BASED, NOT ONLY GAMEWEEK-BASED
----------------------------------------
Gameweek number is a useful prior for information maturity, not the whole policy.

A new manager appointed in GW30 can recreate early-season structural
uncertainty.

A promoted player's role may be well understood by GW3.

A long injury return in GW30 may be more uncertain than a healthy regular in
GW2.

Pulse determines policy from the uncertainty state plus season stage.

======================================================================
1. UNCERTAINTY TAXONOMY
======================================================================

1.1 ALEATORIC UNCERTAINTY
-------------------------
Genuine randomness conditional on the model/world.

Examples:

- whether a shot becomes a goal;
- card occurrence;
- exact bonus tie;
- match score;
- random tactical event.

It cannot be eliminated merely by observing more historical matches, although
its distribution can be estimated better.

Primary representation:

- coherent posterior predictive event and points scenarios.

Decision treatment:

- included in expected utility;
- retained for upside/downside/rank analysis;
- not automatically penalised.

1.2 EPISTEMIC UNCERTAINTY
-------------------------
Uncertainty from limited knowledge.

Examples:

- player scoring ability;
- promoted-team strength;
- new manager's lineup;
- injury readiness;
- model parameters;
- unobserved role hierarchy.

It can often reduce through:

- matches;
- lineups;
- market movement;
- training reports;
- better models/data.

Decision treatment:

- hierarchical shrinkage;
- posterior parameter draws;
- regret/robustness;
- value-of-information analysis.

1.3 MARKET UNCERTAINTY
----------------------
Uncertainty in using markets as evidence:

- operator disagreement;
- de-vig method;
- sparse props;
- stale/delayed quotes;
- settlement rules;
- exchange spread/liquidity;
- bookmaker dependence.

Representation:

- DMFP-06 bounds, disagreement, source/method draws.

1.4 MODEL UNCERTAINTY
---------------------
Uncertainty over:

- Poisson versus flexible score models;
- player-minutes model family;
- calibration form;
- BPS residual model;
- price model;
- optimisation terminal value.

Representation:

- predictive model ensemble;
- model-family scenarios;
- stacking weights;
- challenger disagreement.

1.5 LINEUP UNCERTAINTY
----------------------
Operationally separated because it dominates FPL outcomes:

- availability;
- start/bench/out;
- minute limit;
- tactical rotation;
- formation;
- substitutions.

Lineup uncertainty contains both:

- aleatoric manager choice;
- epistemic lack of knowledge.

Representation:

- DMFP-07 coherent lineup/minute scenarios.

1.6 DATA-SOURCE UNCERTAINTY
---------------------------
- missing fields;
- conflicting reports;
- stale data;
- mapping ambiguity;
- provider outage;
- free-tier coverage;
- manual transcription;
- retrospective correction.

Representation:

- source-quality state;
- missing reason;
- alternative source scenarios;
- operational failure scenarios.

1.7 RULE UNCERTAINTY
--------------------
- target-season game not launched;
- ambiguous official wording;
- undocumented API behaviour;
- mid-season correction;
- chip/rule change.

Representation:

- candidate rulesets;
- blocking state for critical rules;
- sensitivity rescoring where nonblocking.

1.8 STRUCTURAL / REGIME UNCERTAINTY
-----------------------------------
Uncertainty that the data-generating mechanism changed:

- new manager;
- promoted club;
- major transfer;
- tactical system;
- competition/rule change;
- post-World-Cup/preseason state;
- injury-return regime.

This is not handled adequately by only widening a normal parameter interval.

Representation:

- discrete regimes/model classes;
- change-point probabilities;
- mixture priors;
- scenario branches.

1.9 OPERATIONAL UNCERTAINTY
---------------------------
- source unavailable;
- quota exhausted;
- code/model failure;
- missed deadline;
- clock drift;
- stale bundle.

Treatment:

- fail-closed conditions;
- fallback policy;
- operational penalties/chance constraints.

1.10 STRATEGIC UNCERTAINTY
--------------------------
- future rank;
- effective ownership;
- rivals' actions;
- chip timing;
- future fixture announcements;
- future price moves.

Some belongs in later modules.
DMFP-10 defines scenario representation and information value.

1.11 UNCERTAINTY LEDGER
-----------------------
Every projection/decision includes:

- uncertainty type;
- affected variable;
- representation;
- reducible?;
- likely information arrival;
- deadline;
- impact;
- decision sensitivity;
- mitigation.

======================================================================
2. POSTERIOR PREDICTIVE HIERARCHY
======================================================================

2.1 THREE NESTED LEVELS
-----------------------
Pulse distinguishes:

WORLD / STRUCTURAL DRAW
- ruleset;
- manager regime;
- model family;
- promoted-team translation;
- source reliability;
- price mechanism regime.

PARAMETER / EPISTEMIC DRAW
- team/player abilities;
- lineup coefficients;
- calibration parameters;
- market weights;
- price parameters.

OUTCOME / ALEATORIC DRAW
- lineup choice;
- score;
- events;
- FPL points;
- price realization.

2.2 NESTED SCENARIO ID
----------------------
Each scenario stores:

- structural_world_id;
- model_family_ids;
- parameter_draw_id;
- outcome_draw_id;
- source_state_id;
- ruleset_scenario_id;
- probability/weight.

2.3 WHY NESTING MATTERS
-----------------------
If all draws are flattened without labels:

- model disagreement cannot be separated from match randomness;
- robust regret cannot target epistemic worlds;
- value of information cannot identify reducible uncertainty;
- confidence becomes opaque.

2.4 LAW OF TOTAL VARIANCE
-------------------------
Conceptually:

    Var(Y)
      =
      E[Var(Y | epistemic state)]
      +
      Var(E[Y | epistemic state])

First term:
conditional outcome/aleatoric uncertainty.

Second:
epistemic/world uncertainty.

Use this decomposition for diagnostics, while acknowledging that the split
depends on model framing.

2.5 ACTION UNCERTAINTY
----------------------
For each action a, compute:

- mean utility;
- within-world outcome variance;
- between-world expected-utility variance;
- robust regret;
- downside by source/model world.

======================================================================
3. BAYESIAN PRIORS
======================================================================

3.1 PURPOSE
-----------
Priors stabilise predictions where evidence is limited and encode structured
knowledge.

3.2 PRIOR SOURCES
-----------------
- prior Premier League seasons;
- recent season;
- lower/other league translated performance;
- bookmaker markets;
- team/player role groups;
- manager history;
- promoted-club history;
- age/position;
- preseason evidence;
- source reliability.

3.3 NO DOUBLE COUNTING
----------------------
If bookmaker odds already enter the likelihood/current calibration, do not also
encode the same odds as an independent prior without accounting for dependence.

Likewise:

- player historical statistics;
- official FPL xG fields derived from those statistics;
- public model using the same data;

are not independent evidence.

3.4 PRIOR PREDICTIVE CHECK
--------------------------
Before fitting:

- simulate lineups, scores, minutes, points and prices;
- inspect plausible ranges;
- inspect promoted/new-manager states;
- reject absurdly narrow/wide priors.

3.5 WEAKLY INFORMATIVE, NOT VAGUE
---------------------------------
Use priors strong enough to regularise sparse parameters but wide enough to
permit genuine breaks.

3.6 POWER/DISCOUNTED PRIORS
---------------------------
Historical evidence may be discounted by:

- age;
- league transfer;
- manager change;
- role change;
- injury;
- rules change.

A prior-power/discount factor is parameter-specific and validated.

3.7 MARKET PRIORS
-----------------
Markets can anchor:

- team score;
- selected player events.

They do not directly define:

- minutes;
- all assists;
- BPS;
- price changes.

======================================================================
4. HIERARCHICAL SHRINKAGE AND PARTIAL POOLING
======================================================================

4.1 PRINCIPLE
-------------
Sparse individual estimates borrow strength from related groups.

Examples:

- player from tactical role;
- promoted club from promoted-club and league priors;
- manager from league and prior-club behaviour;
- injury return from diagnosis/position/age;
- bookmaker weight from market-type population.

4.2 ADAPTIVE SHRINKAGE
----------------------
The model learns the amount of pooling.

Small-sample units shrink more.
Established units with repeated evidence retain more individual signal.

4.3 GROUPS
----------
Potential levels:

- global;
- competition;
- season;
- team;
- manager;
- manager-team regime;
- FPL position;
- tactical role;
- player;
- market/operator;
- injury class;
- price bracket.

4.4 NEW PLAYER
--------------
A new signing is not assigned the league mean blindly.

Prior mixture may use:

- prior club/league;
- role;
- transfer context;
- age;
- markets;
- preseason;
- new-team depth.

4.5 PROMOTED CLUB
-----------------
Use a distribution, not fixed promotion penalty.

Borrow from:

- historical promoted clubs;
- underlying team metrics;
- market strength;
- squad change;
- manager;
- Championship/other league translation.

4.6 NEW MANAGER
---------------
A new manager-team regime combines:

- manager prior-club tendencies;
- club squad/history;
- league manager distribution;
- preseason/current evidence.

Uncertainty is wider than for an established regime.

======================================================================
5. PARAMETER-SPECIFIC LEARNING SPEED
======================================================================

5.1 NOT ALL PARAMETERS UPDATE EQUALLY
-------------------------------------
One early match can be highly informative about:

- starting lineup;
- formation;
- set pieces;
- penalty taker;
- role.

It is weak evidence about:

- finishing ability;
- long-run assist quality;
- team defensive strength;
- card propensity.

5.2 FAST-LEARNING STATES
------------------------
- lineup role;
- squad hierarchy;
- tactical formation;
- set-piece responsibility;
- injury readiness;
- manager selection policy.

5.3 SLOW-LEARNING ABILITIES
---------------------------
- finishing;
- chance creation;
- defensive ability;
- goalkeeper save ability;
- long-term team strength.

5.4 DYNAMIC UPDATE
------------------
Each parameter family has:

- transition variance;
- historical discount;
- observation likelihood;
- change-point sensitivity.

5.5 EARLY-SEASON SURPRISE
-------------------------
A surprising GW1 event triggers:

- posterior update;
- change-point/regime evidence;
- source review.

It does not automatically replace the prior.

5.6 CHANGE-POINT PROBABILITY
----------------------------
For role/team parameters:

- maintain probability of old versus new regime;
- update with lineups/events;
- expand uncertainty while unresolved.

5.7 FASTER UPDATING
-------------------
"Faster early-season updating" means:

- run the posterior after every meaningful observation;
- allow high-information role evidence to move rapidly;
- reduce confidence lag;
- retain correct prior strength for noisy statistics.

It does not mean recency-chasing.

======================================================================
6. MODEL ENSEMBLES AND MODEL UNCERTAINTY
======================================================================

6.1 CANDIDATE MODELS
--------------------
Every major module maintains:

- baseline;
- primary;
- challengers;
- structural alternatives.

6.2 NO WINNER-TAKE-ALL BY DEFAULT
---------------------------------
Selecting one model and ignoring selection uncertainty can produce
overconfident decisions.

6.3 BAYESIAN MODEL AVERAGING
----------------------------
BMA is a coherent option when candidate models and priors are well specified.

But in the M-open setting—where no candidate is assumed true—posterior model
probability can be unstable or overconfident.

6.4 PREDICTIVE STACKING
-----------------------
Selected ensemble policy after enough validation:

- combine predictive distributions;
- weights learned by out-of-time proper scoring;
- regularised;
- time-safe;
- optionally hierarchical by context.

Yao, Vehtari, Simpson and Gelman recommend stacking predictive distributions in
M-open settings and compare it favourably with several alternatives.

6.5 HIERARCHICAL STACKING
-------------------------
Potential weights vary by:

- early/late season;
- manager regime;
- market coverage;
- player type;
- promoted club;
- injury return.

Weights are partially pooled to avoid overfitting.

6.6 INITIAL POLICY
------------------
Before enough data:

- primary model weight: 0.60;
- baseline/challenger mixture: remaining 0.40 according to predeclared
  research evidence;
- wide sensitivity;
- no context-specific learned weights.

These exact weights are provisional configuration, not scientific constants.

6.7 ENSEMBLE UNCERTAINTY
------------------------
Report:

- ensemble mean;
- within-model uncertainty;
- between-model mean disagreement;
- model weights;
- performance history.

6.8 MODEL PROMOTION
-------------------
A model may receive more weight after prospective proper-score improvement.
It is not removed solely due one bad Gameweek.

======================================================================
7. SCENARIO CONSTRUCTION
======================================================================

7.1 SCENARIO FAN
----------------
The full posterior predictive simulations from DMFP-09 form a scenario fan.

7.2 SCENARIO TREE
-----------------
A multistage decision problem requires branching at information/decision times.

Nodes represent what is known then.

7.3 FPL TREE STAGES
------------------
Example:

Stage 0 — current deadline:
- transfer;
- lineup;
- captain;
- chip.

Stage 1 — current Gameweek outcomes:
- points;
- injuries;
- price changes;
- role evidence;
- fixture news.

Stage 2 — next deadline:
- adapt transfer/lineup.

Continue over selected horizon.

7.4 NONANTICIPATIVITY
---------------------
Actions at a tree node may depend only on information revealed on the path to
that node.

They cannot depend on future outcomes.

7.5 BRANCH VARIABLES
--------------------
Branch explicitly only on high-impact uncertainty that:

- materially changes action;
- can be revealed before a future action;
- is not adequately represented by continuous scenario sampling.

Examples:

- player becomes regular starter;
- injury return delayed;
- manager switches formation;
- blank/double announced;
- price rise/fall;
- penalty taker resolved;
- rules clarification.

7.6 NO FULL COMBINATORIAL TREE
------------------------------
Branching every player event causes explosion.

Use:

- sampled trajectories;
- clustered latent worlds;
- limited branch variables;
- rolling horizon;
- terminal value approximation.

7.7 SCENARIO REDUCTION
----------------------
If the optimiser cannot ingest the full matrix:

- preserve probability distribution and decision-relevant distances;
- use forward selection/clustering/optimal-transport concepts;
- validate that the selected action and objective remain stable;
- retain rare adverse/upside scenarios.

7.8 REDUCTION TARGET
--------------------
Reduce for decision equivalence, not merely statistical similarity.

Compare:

- selected transfers;
- expected points;
- robust regret;
- tail probabilities;
- covariance.

7.9 TREE VERSIONING
-------------------
Every tree/reduced scenario set stores:

- source scenario IDs;
- clustering/reduction method;
- probability mass;
- decision-stage structure;
- information revelation;
- approximation error.

======================================================================
8. ROLLING-HORIZON POLICY
======================================================================

8.1 SELECTED APPROACH
---------------------
Solve a manageable multistage problem at every deadline using current
information, execute only the immediate action, then re-solve.

8.2 WHY
-------
Full-season scenario trees are computationally infeasible and brittle.

Rolling horizon allows:

- updated market data;
- injuries;
- fixtures;
- price changes;
- role information;
- rank/chip state.

8.3 HORIZON
-----------
Horizon is adaptive.

Typical:

- early season: 6–8 Gameweeks explicit plus terminal value;
- stable middle: 5–7;
- approaching blank/double: extend through the event;
- late season: remaining season;
- chip planning: include all relevant chip windows.

8.4 TERMINAL VALUE
------------------
Avoid myopic transfers by valuing state after explicit horizon.

Terminal value includes:

- projected points beyond horizon;
- bank/team-value affordability;
- free transfers;
- chip inventory;
- fixture structure;
- player contract/price position;
- flexibility;
- uncertainty.

8.5 RE-SOLVE
------------
Every deadline.
Also create interim no-action information checks where a price/news decision is
time-sensitive.

8.6 POLICY EVALUATION
---------------------
Backtest the rolling policy, not only one-step recommendations.

======================================================================
9. EXPECTED UTILITY
======================================================================

9.1 BASELINE
------------
For pure points mode:

    U(points) = cumulative FPL points

The default decision is risk-neutral with respect to correctly modelled FPL
points.

9.2 WHY EXPECTED POINTS
-----------------------
Winning a season generally requires repeatedly selecting actions with strong
expected long-run outcomes.

Research on FPL finds long-term planning and consistently good decisions in a
noisy environment are important indicators of skill.

9.3 UTILITY EXTENSIONS
----------------------
Later modules may include:

- final-rank utility;
- top-k probability;
- relative ownership;
- mini-league utility.

These must be explicit.

9.4 NO HIDDEN RISK AVERSION
---------------------------
A transfer cannot be rejected merely because its points distribution has higher
variance if it has higher expected season points and no structural downside.

9.5 CATASTROPHIC STATES
-----------------------
Chance constraints may protect against:

- fewer than 11 likely players;
- illegal squad;
- no goalkeeper;
- forced chain of hits;
- unresolved deadline/rules;
- excessive nonappearance.

These are operational/squad failure risks, not ordinary football variance.

======================================================================
10. ROBUST OPTIMISATION
======================================================================

10.1 PURPOSE
------------
Robust optimisation protects against misspecified expectations.

10.2 PRICE OF ROBUSTNESS
------------------------
Bertsimas and Sim show how budgeted uncertainty can trade nominal objective
performance for protection without assuming every coefficient simultaneously
takes its worst value.

This motivates a configurable uncertainty budget rather than full worst-case
FPL planning.

10.3 BUDGETED PLAYER UNCERTAINTY
-------------------------------
For uncertain expected player contributions:

- each can deviate within a calibrated epistemic band;
- uncertainty budget Gamma limits how many adverse deviations are assumed
  jointly.

Use carefully because player errors are correlated.

10.4 CORRELATION
----------------
Prefer scenario-induced or factor-based uncertainty sets over independent boxes.

Examples:

- one team attack downgrade affects several players;
- manager rotation affects role group;
- source outage affects many markets.

10.5 SELECTED PRODUCTION ROBUSTNESS
-----------------------------------
Initial production:

1. posterior expected utility;
2. robust-regret penalty across model/regime worlds;
3. chance constraints for squad failure;
4. action sensitivity report;
5. optional budgeted uncertainty challenger.

10.6 NOT SELECTED AS DEFAULT
----------------------------
Pure maximin/worst-case points.

Reason:

- unrealistically pessimistic;
- can select low-upside teams;
- all uncertainty extremes rarely co-occur;
- may sacrifice too many expected points.

10.7 ROBUST FEASIBILITY
-----------------------
Legal/budget feasibility is deterministic under each price/state scenario.
Actions must remain implementable where promised.

10.8 PRICE OF ROBUSTNESS REPORT
-------------------------------
For robustness level r:

- expected-points loss versus nominal;
- regret reduction;
- downside protection;
- selected action changes;
- failure probability.

No robustness parameter is approved without this frontier.

======================================================================
11. DISTRIBUTIONALLY ROBUST OPTIMISATION
======================================================================

11.1 PURPOSE
------------
The empirical posterior/scenario probabilities themselves may be wrong.

DRO optimises against a set of distributions around the nominal forecast.

11.2 WASSERSTEIN AMBIGUITY
--------------------------
Esfahani and Kuhn show that data-driven DRO over Wasserstein balls can have
finite-sample guarantees and tractable reformulations in many settings.

11.3 FPL APPLICATION
--------------------
An ambiguity set may perturb:

- scenario probabilities;
- player mean distributions;
- correlated team/regime outcomes;
- price paths.

11.4 RADIUS
-----------
Radius cannot be arbitrary.

Candidates:

- bootstrap;
- held-out calibration error;
- concentration result;
- prospective decision performance;
- season stage.

11.5 EARLY SEASON
-----------------
Larger ambiguity set due:

- sparse current-season data;
- structural change;
- source/model uncertainty.

11.6 LATE SEASON
----------------
Smaller for stable player/team parameters, but not necessarily for:

- new manager;
- injury return;
- blank/double schedule;
- new signing.

11.7 PRODUCTION STATUS
----------------------
CHALLENGER, not initial default.

Promotion requires:

- tractability;
- interpretable radius;
- better out-of-time utility/regret;
- no excessive conservatism;
- stable selected actions.

======================================================================
12. CONDITIONAL VALUE AT RISK
======================================================================

12.1 DEFINITION
--------------
For loss L, CVaR_beta is the expected loss in the worst beta-tail beyond the
corresponding quantile, under standard conditions.

Rockafellar and Uryasev provide a practical optimisation representation.

12.2 FPL USE
------------
Potential use:

- downside of a transfer plan;
- risk of a severely depleted squad;
- tail of points shortfall against a baseline;
- rank utility later.

12.3 NOT A DEFAULT POINTS PENALTY
--------------------------------
CVaR of weekly FPL points can over-penalise legitimate upside.

Use primarily for:

- operational/squad-availability tail;
- robust alternative reporting;
- explicit rank-risk mode.

12.4 LOSS DEFINITION
--------------------
Never use raw negative points without context.

Candidate loss:

    loss_s(a)
      =
      points_s(baseline plan)
      - points_s(a)

This measures action regret/shortfall relative to a feasible baseline.

12.5 CONFIGURATION
------------------
- tail level;
- horizon;
- baseline;
- weight;
- mode;
- season stage.

======================================================================
13. SENSITIVITY ANALYSIS
======================================================================

13.1 PURPOSE
------------
A decision is fragile if small plausible changes reverse it.

13.2 ONE-WAY
------------
Vary:

- p_start;
- minutes;
- team goals;
- price rise/fall;
- fixture;
- model weight;
- market confidence;
- future budget value.

13.3 MULTIWAY
-------------
- player unavailable + rival starts;
- new manager formation;
- team attack downgrade;
- blank fixture announcement;
- source failure.

13.4 DECISION-SWITCH THRESHOLD
------------------------------
Report:

- parameter value where action changes;
- current posterior probability of crossing it;
- information likely before decision;
- value of resolving it.

13.5 TORNADO
------------
Rank uncertain inputs by change in action utility/regret.

13.6 GLOBAL SENSITIVITY
-----------------------
For nonlinear decisions, use:

- scenario-based variance decomposition;
- Sobol/Shapley effects where computationally justified;
- EVPPI as decision-focused alternative.

13.7 SHADOW PRICES
------------------
Optimiser dual/marginal values:

- £0.1 budget;
- one free transfer;
- club slot;
- position slot;
- chip;
- bench reliability.

Integer optimisation dual values can be unstable; validate through finite
counterfactual re-optimisation.

13.8 STABILITY SCORE
--------------------
Action stability:

- fraction of posterior/model worlds selecting action;
- utility gap;
- switch probability;
- regret distribution.

======================================================================
14. VALUE OF INFORMATION
======================================================================

14.1 PRINCIPLE
--------------
Uncertainty matters for decisions only when resolving it can change action or
utility.

14.2 EXPECTED VALUE OF PERFECT INFORMATION
------------------------------------------
For uncertain state theta:

    EVPI
      =
      E_theta [ max_a E[U(a) | theta] ]
      -
      max_a E_theta [ U(a) ]

EVPI is an upper bound on the value of any information about theta.

14.3 EXPECTED VALUE OF SAMPLE INFORMATION
-----------------------------------------
For possible observation Y:

    EVSI
      =
      E_Y [ max_a E[U(a) | Y] ]
      -
      max_a E[U(a)]

14.4 PARTIAL PERFECT INFORMATION
--------------------------------
EVPPI for:

- player availability;
- new manager formation;
- penalty taker;
- fixture schedule;
- price change;
- model family.

This identifies which uncertainty is decision-critical.

14.5 INFORMATION COST
---------------------
Net information value:

    net_EVSI
      =
      EVSI
      - acquisition/time cost
      - price-move risk
      - deadline execution risk
      - lost-option cost

14.6 WAIT OR ACT
----------------
Wait when:

    expected value of future information
    + preserved flexibility

exceeds:

    expected price/budget loss
    + points lost by delay
    + execution risk.

14.7 EXAMPLE
-------------
A doubtful transfer target may rise tonight before tomorrow's press conference.

Pulse compares:

ACT NOW:
- price protected;
- injury/role risk;
- irreversible transfer.

WAIT:
- possible £0.1 loss;
- improved availability evidence;
- preserved transfer.

No generic "always wait for press conferences" or "always beat price rises"
rule is allowed.

14.8 VALUE OF INFORMATION REPORT
--------------------------------
For each close decision:

- uncertainty;
- EVPI/EVPPI estimate;
- next information event;
- time;
- expected action switch;
- price risk;
- recommendation: ACT / WAIT / NO MATERIAL INFORMATION VALUE.

14.9 DATA ACQUISITION
---------------------
VOI can prioritize:

- manual odds capture;
- press conference review;
- lineup-source verification;
- provider quota;
- model research.

======================================================================
15. VALUE OF WAITING AND FLEXIBILITY
======================================================================

15.1 REAL-OPTION ANALOGY
------------------------
A transfer is partly irreversible:

- free transfer consumed;
- previous purchase price lost;
- future reversal costs another transfer;
- price movement can close/reopen routes.

Waiting can preserve an option to adapt after information arrives.

15.2 WAITING IS NOT FREE
------------------------
Costs:

- price change;
- injury to current player;
- missed points;
- deadline risk;
- lost free-transfer capacity;
- lost team-value appreciation.

15.3 FLEXIBILITY TYPES
----------------------
SQUAD FLEXIBILITY:
multiple valid starters/bench.

PRICE FLEXIBILITY:
bank and price points that support alternative transfers.

TRANSFER FLEXIBILITY:
free transfers and no forced moves.

FORMATION FLEXIBILITY:
multiple legal formations without hits.

CLUB-SLOT FLEXIBILITY:
open slots for high-value teams.

CHIP FLEXIBILITY:
uncommitted chips and routes to planned weeks.

INFORMATION FLEXIBILITY:
ability to wait for evidence.

15.4 FLEXIBILITY VALUE
----------------------
Define:

    Flex(a)
      =
      E_future_info [
        max_future_actions U
      ]
      -
      max_fixed_future_plan E[U]

or approximate by comparing adaptive re-optimisation with frozen plan.

15.5 FEASIBLE-ACTION BREADTH
----------------------------
Supplementary metric:

- number/weighted quality of plausible future actions;
- affordability range;
- transfer distances;
- club/position bottlenecks.

Count alone is not value; weight by future utility.

15.6 PLAYER FLEXIBILITY
-----------------------
A player can provide option value through:

- stable minutes;
- multiple future fixtures;
- price bracket;
- easy upgrade/downgrade route;
- low forced-transfer risk;
- positional scarcity.

This does not mean "versatile real-world player" unless reflected in FPL state.

======================================================================
16. TEAM VALUE AND BUDGET POLICY
======================================================================

16.1 STATE VARIABLES
--------------------
- squad market value;
- bank;
- player purchase prices;
- selling prices;
- unrealised price gains;
- expected price paths;
- affordability set.

16.2 OFFICIAL REFERENCE MECHANICS
---------------------------------
Official 2025/26 guidance states:

- prices may change by £0.1m per day according to transfer activity;
- a fall is fully passed to selling value;
- only half a rise is retained, rounded down to £0.1m.

Target 2026/27 must be verified.

16.3 TEAM VALUE IS NOT CASH
---------------------------
Reported squad value can overstate usable budget because selling-value rules
retain only part of rises.

Use:

- liquidation selling value;
- bank;
- ownership-spell purchase price;
- route-specific affordability.

16.4 MARGINAL BUDGET VALUE
--------------------------
Counterfactual finite difference:

    v_money(delta)
      =
      V*(state with delta extra bank)
      -
      V*(state)

Evaluate delta = £0.1m and relevant increments.

16.5 EARLY-SEASON RUNWAY
------------------------
Early extra budget may be more valuable because more future decisions remain.

But its marginal value can be zero if:

- optimal squad is already affordable;
- price structure has no useful upgrade;
- future price paths offset it;
- transfer routes are constrained elsewhere.

16.6 LATE-SEASON VALUE
----------------------
By GW30:

- fewer deadlines remain;
- prices may be less useful;
- budget matters only for specific desired moves/chips;
- points and fixture timing dominate.

16.7 PRICE-CHASING GATE
-----------------------
Transfer for expected price movement only when:

- price probability sufficiently strong;
- selling-price impact is real;
- future budget shadow value positive;
- no high-value information is imminent;
- transfer remains points-competitive;
- no hit or lock-in creates excessive regret.

16.8 HITS FOR TEAM VALUE
------------------------
No categorical ban, but require:

    expected discounted future point value of extra usable budget
    + immediate points value
    > 4-point hit
      + lost free transfer
      + uncertainty/lock-in cost.

In most ordinary cases, budget alone is unlikely to clear this hurdle.

16.9 PRICE-DROP AVOIDANCE
-------------------------
A predicted fall can be more directly damaging than one predicted rise is
beneficial because the full fall affects selling value while profit requires
larger rises.

Still account for:

- current player's expected points;
- possibility of price-model error;
- value of waiting;
- replacement risk.

16.10 TEAM-VALUE OBJECTIVE ERROR
--------------------------------
Prohibited:

    maximise team value.

Selected:

    maximise expected season points with team value embedded through future
    affordability and terminal state.

======================================================================
17. EARLY-SEASON STRUCTURAL POLICY
======================================================================

17.1 EARLY-SEASON WINDOW
------------------------
Default:

- preseason through GW5: high structural uncertainty;
- GW6–10: transition;
- state-specific overrides.

This is configuration, not a universal law.

17.2 PRIOR STRENGTH
-------------------
Greater shrinkage toward:

- market team strength;
- historical ability;
- role/manager priors;
- promoted-club distributions.

17.3 INTERVAL WIDTH
------------------
Wider:

- p_start;
- team goals;
- player shares;
- BPS residual;
- price changes;
- model weights;
- fixture/manager regimes.

17.4 CONFIDENCE CAPS
--------------------
Examples:

- new manager with <3 competitive lineups cannot receive confidence A for role;
- new player with no target-league competitive minutes confidence capped;
- promoted team strength remains structurally uncertain;
- early rules/source changes cap confidence.

17.5 FLEXIBILITY
----------------
Early squads prefer, all else equal:

- fewer likely forced transfers;
- reliable bench;
- price routes;
- bank where marginal option value is positive;
- open club slots;
- rollable transfer state.

17.6 LONG-TERM COMMITMENTS
--------------------------
Require a higher robust evidence margin for:

- expensive low-liquidity price bracket;
- double/triple team exposure under uncertain manager;
- injury-return player;
- one-week bandwagon;
- player requiring multiple future transfers to exit.

17.7 HITS
---------
Early hits face:

- 4-point immediate cost;
- higher model uncertainty;
- high reversal probability.

Use only when robust season utility improves, not because an observed GW1 score
was surprising.

17.8 CAPTAINCY
----------------
Do not make captaincy "safe" by automatically avoiding variance.

Use the full expected points/rank utility.
Lineup uncertainty and catastrophic nonappearance are real risks; ordinary
goal variance is not a reason to avoid a superior expected captain.

17.9 MODEL UPDATE FREQUENCY
---------------------------
Update after:

- every competitive lineup;
- significant market move;
- injury/training evidence;
- manager formation;
- set-piece evidence;
- price data.

17.10 ALERT
-----------
Early-season "structural surprise":

- actual lineup low posterior probability;
- role/tactic outside scenario set;
- promoted-team performance outside interval;
- repeated source disagreement.

Triggers scenario/model review.

======================================================================
18. MID-SEASON POLICY
======================================================================

18.1 GW6–24 TYPICAL
-------------------
- current-season evidence dominates more;
- shrinkage remains;
- model weights learned cautiously;
- narrower structural intervals;
- expected points carry more weight relative to flexibility;
- price value remains instrumental;
- rolling horizon focuses fixtures and chips;
- robust regret still applied to injury/role uncertainty.

18.2 ESTABLISHED REGULAR
------------------------
High confidence possible if:

- manager stable;
- lineup history;
- market/source agreement;
- no injury regime.

18.3 NO COMPLACENCY
-------------------
Regime changes reset uncertainty.

======================================================================
19. LATE-SEASON POLICY
======================================================================

19.1 GW25–31
------------
Common emphasis:

- blank/double uncertainty;
- fixture announcements;
- chip routes;
- free-transfer inventory;
- short-to-medium horizon;
- schedule VOI;
- team value only where it enables planned structure.

19.2 GW32–38
------------
- horizon becomes remaining season;
- terminal value fades to zero at GW38;
- unused chips/free transfers expire;
- team-value appreciation after final use has no value;
- immediate/remaining points dominate;
- rank utility may alter variance preferences explicitly;
- information timing remains important;
- long-term lock-in penalty approaches zero where no future reversal needed.

19.3 GW30 EXAMPLE
-----------------
A GW30 transfer may rationally be more aggressive than GW2 if:

- the role is well estimated;
- only eight/nine weeks remain;
- fixture/chip path is clear;
- team value has little later value;
- rank utility rewards upside.

It may be more conservative if:

- blank/double schedule unresolved;
- new manager;
- injury return;
- transfer would destroy a valuable chip route.

======================================================================
20. GAMEWEEK 2 VERSUS GAMEWEEK 30
======================================================================

20.1 BELIEFS
------------
GW2:
- prior-heavy;
- one current match is limited evidence;
- structural mixture wide;
- promoted/new-manager uncertainty high.

GW30:
- season data usually dominant;
- narrower for established states;
- structural reset only where new shocks exist.

20.2 TRANSFER HORIZON
---------------------
GW2:
- 36+ future deadlines;
- reversal and price-route consequences large;
- terminal value/flexibility material.

GW30:
- short remaining horizon;
- immediate fixture/chip points larger share;
- long-run price growth has little value.

20.3 TEAM VALUE
---------------
GW2:
- positive marginal value can compound through future affordability;
- price fall/rise probabilities matter;
- still not worth sacrificing robust points blindly.

GW30:
- value near zero unless it unlocks a specific remaining move;
- do not chase abstract squad value.

20.4 WAITING
------------
GW2:
- information about manager roles and new players can have high value;
- price movement can also be rapid;
- formal EVSI trade-off.

GW30:
- information about blanks, doubles, injury and chip route can be high value;
- less role-learning for established players.

20.5 ROBUSTNESS
---------------
GW2:
- higher regret penalty for structural/model worlds;
- larger ambiguity set;
- action stability matters.

GW30:
- lower model ambiguity for stable players;
- robustness focuses schedule/injury;
- rank utility may permit targeted risk.

20.6 FLEXIBILITY
----------------
GW2:
- broad route value;
- roll transfer frequently valuable;
- bank/bench/price structure important.

GW30:
- flexibility means exact blank/double/chip route;
- unused flexibility soon expires.

20.7 UPDATING
-------------
GW2:
- fast for role;
- slow for ability;
- confidence cap.

GW30:
- mature estimates update normally;
- structural shocks still update fast.

20.8 PRACTICAL DEFAULT
----------------------
GW2 default recommendation threshold:
require robust expected-season improvement and low reversal probability.

GW30 default:
require expected remaining-season/rank utility improvement; tolerate more
commitment where no long horizon remains.

21. DECISION MODES
======================================================================

21.1 EXPECTED_POINTS
--------------------
Maximise posterior expected remaining points.

Default benchmark.

21.2 ROBUST_POINTS
------------------
Expected points minus robust-regret/lock-in penalties.

Default early-season production recommendation.

21.3 FLEXIBILITY
----------------
Maximise near-optimal points plus option/flexibility.

Used for close decisions.

21.4 TEAM_VALUE_AWARE
---------------------
Expected points plus modelled marginal future budget value.

Never pure team value.

21.5 DOWNSIDE_PROTECTED
-----------------------
Expected utility with CVaR/chance constraints.

Used for severe squad fragility.

21.6 RANK_AWARE
----------------
DMFP-14 objective.
Not active by default in DMFP-10.

21.7 OUTPUT
-----------
Compare all relevant modes and state why the selected action wins.

22. DECISION CONFIDENCE AND ACTION GATES
======================================================================

22.1 CONFIDENCE IS NOT EXPECTED VALUE
-------------------------------------
High-EV action can be low confidence.
Low-EV action can be high confidence.

Report separately.

22.2 ACTION CONFIDENCE DIMENSIONS
---------------------------------
- utility gap;
- probability action is optimal;
- robust regret;
- switch probability;
- source/model confidence;
- information arrival;
- reversibility;
- execution risk.

22.3 GATES
----------
AUTO-RECOMMEND:
strong utility gap, stable, legal, source/rules healthy.

RECOMMEND_WITH_CAUTION:
positive but model-sensitive.

WAIT_FOR_INFORMATION:
net EVSI positive and execution feasible.

HUMAN_REVIEW:
structural/rule/source conflict.

NO_ACTION/ROLL:
no alternative robustly clears cost.

BLOCKED:
rules/deadline/manager state invalid.

22.4 TRANSFER HIT GATE
----------------------
Require:

- posterior expected gain > hit;
- robust lower comparison acceptable;
- reversal probability;
- free-transfer value;
- team-value/flexibility accounted;
- no imminent higher-VOI information ignored.
