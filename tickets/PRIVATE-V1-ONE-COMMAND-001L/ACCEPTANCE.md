# PRIVATE-V1-ONE-COMMAND-001L engineering acceptance

The 001K candidate universe, retained incoming set, legal 0/1/2-transfer actions and unique
resulting squads remain unchanged. Before Stage 11 selects a policy, every unique root squad is
evaluated through one node-scoped exact tactical kernel and the existing `(node, squad)` memo is
prefilled.

The kernel parses exact scenario weights once, uses an algebraically exact common integer
denominator, groups identical appearance states, reuses captain/vice values across squads and
evaluates all bench orders for one XI without repeating its scenario interpretation. Autosub
selection remains exactly equivalent to the accepted resolver. The selected tactic is always
re-evaluated by the existing canonical scenario evaluator before publication.

For each fixed squad, old and new outputs must be identical for lineup, bench, captaincy,
expected objective, scenario vector, distribution and metrics, tie count, deterministic
signature, solver declaration and plan hash. Batch results are independent of squad input order.
Logical exhaustive-search counters remain unchanged even when physical work is factored.

The private CLI reports truthful `N/total` Stage-10 batch progress, a distinct batch-ready event,
and a distinct Stage-11 policy-selection stage without percentages or ETA. Frozen synthetic
private runs retain the same recommendation and decision semantic hash apart from progress-only
diagnostics.

A deterministic 263-squad, 256-scenario live-shaped benchmark must show no exactness difference
and a substantial reproducible speedup, targeting at least 5x over the retained 001K path without
making CI depend on a fragile absolute duration. Acceptance also requires affected unit,
property, contract and private suites, branch coverage, Ruff, strict mypy, frozen sync, build,
clean-wheel, repository and secret gates, exact-final-SHA CI and the literal GW3 retry when
existing runtime inputs are present.
