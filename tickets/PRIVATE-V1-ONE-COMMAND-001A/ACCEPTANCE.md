# PRIVATE-V1-ONE-COMMAND-001A engineering acceptance

`dmf pulse --entry-id <id>` is the only ordinary operator input. It performs sequential,
bounded HTTPS GET requests through a closed official-FPL path grammar; obtains authenticated
pre-deadline current-team facts from `/api/my-team/{entry_id}/`; and never accepts a token as a
CLI option. The token is read from `DMF_FPL_BEARER_TOKEN` or a hidden interactive prompt and is
never retained or disclosed.

The new `fpl_official_private_operator_initiated_read_v1` profile is distinct from and does not
modify `fpl_official_private_manual_v1`. It records the operator's explicit acceptance of the
contractual risk in low-volume private use. It is not a claim of Premier League permission,
legal advice, a redistribution right, or production authority. Raw and derived storage, cache,
backup, public display, redistribution and model training remain denied with zero retention.

The command resolves a future target deadline from official event flags, compiles the current
catalogue and provider-observed manager state, uses completed checked live events without
zero-filling missing minutes, invokes the accepted
`REGULARISED_EMPIRICAL_BAYES_COHERENCE_V1` Stage-7 path, acquires current Odds and OpenFootball
prior inputs, constructs deterministic identities, and generates ownership, the complete
provider-selectable non-squad candidate universe and explicit post-GW1 stale-prior fallbacks.
It then invokes the existing Stage 8, Stage 9, exact Stage-10/11 and captaincy services. A
no-transfer action and aligned no-action comparator remain mandatory.

The offline E2E starts at fake provider HTTP responses and crosses the real new orchestration,
parser, model, scorer, optimiser and report boundaries. CI never calls live FPL. A genuine run
is complete only when both required credentials are available and the command emits an actual
recommendation; engineering readiness does not relabel a blocked run as successful. No PR,
merge, tag, writeback or production activation is authorised.
