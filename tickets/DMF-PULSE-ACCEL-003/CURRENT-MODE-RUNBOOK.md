# Current-mode execution and operator boundary

`dmf dashboard` remains blocked for real acquisition. No production refresh
approval is enrolled. `dmf dashboard --demo` preserves the existing synthetic
demonstration. `dmf dashboard --current-demo` runs the new current-mode process
entrypoint with authenticated repository-owned input transports, real provider
parsers, and the accepted Stage-7/8/9/10/11 application services. Its browser
label is `SYNTHETIC_CURRENT_MODE`; it supplies no real recommendation evidence.

Pair through the terminal's one-time code at the printed loopback URL. Press
Refresh explicitly and select one or three Gameweeks. Browser reload, page
navigation, eligibility display and status polling acquire no provider data.
My Team, Players and Decisions share one completed result and job identifier.
Unavailable catalogue entries remain visible. Cancel, supersession, failure,
deadline, grant expiry, finite presentation lifetime and shutdown clear the
result. No command writes to an FPL account. Existing private browser controls,
no-store headers and bounded disposable worker termination remain mandatory.

Current-demo creates only an owned synthetic usage directory, by default under
the operating system temporary directory. `--control-dir` selects its parent
for explicit test inspection. That option is rejected in production mode.
Control records contain hashes, opaque references, UTC timestamps and counters;
they contain no model results, source bodies or credentials.

Future real startup requires a separately reviewed installed enrollment plus
`--refresh-approval <identifier> --entry-id <approved-entry> --deadline-at
<qualified-UTC-deadline>`. The deadline must equal the trusted enrollment and
later match the official deadline observed by the existing FPL client. The
installed enrollment fixes account, source/profile hashes, exact GET routes,
purpose, season, horizons, plan/quota evidence, budgets, review, package content
fingerprint, consumption policy and expiry. Browser input cannot enroll it.
Credentials are resolved only after these gates and a durable reservation.
Source transports recheck the claimed grant and route budget before each send.
Acquisition closes before modelling; computation never authorizes another GET.

The current worker authenticates the complete presentation against its grant,
accepted decision and actionability receipt using the ephemeral worker claim.
The parent checks that binding, exact code/cutoff/deadline/capture, Gameweek and
projection identities before publication and throughout presentation lifetime.
This IPC integrity check grants no provider or retention rights.

Production control uses an explicitly initialized PostgreSQL account ledger.
`DMF_CONTROL_DATABASE_URL` is a server-only connection reference resolved inside
an authorized transaction, never in browser, process launch or stored controls.
The test reference is restricted to owned synthetic sources. Ordinary Refresh
never initializes or resets a missing ledger. Setup, migration, custody and
recovery require the separate operator procedure in CONTROL-STORE.md.

The 40-character implementation field is a truncated SHA-256 of installed
package content, not a Git commit assertion. Every executable file and resource
is included except the exact trusted enrollment metadata resource, avoiding a
self-referential fingerprint. Detached review must bind final Git SHA, complete
wheel SHA, content fingerprint and enrollment-resource SHA together. Installing
a reviewed package is a trusted operator action. There is no caller-selected
enrollment path, environment enrollment, force switch or browser bypass.

Before any separately authorized live pilot, approve the exact current FPL
routes/purpose, a new market profile and account plan/quota, OpenFootball scope,
control metadata custody, qualified deadline, final reviewed release and one
bounded manual refresh. Those approvals are absent here. No real credential
inspection or provider acquisition forms part of engineering acceptance.

Model Performance additionally executes the owned cohort runner. It is separate
from the recommendation run and reports zero qualified real cohort members,
unavailable B0-B5 benchmarks and forbidden promotion. Starts/minutes evidence is
also separate and inactive; neither synthetic diagnostic rewires player priors.
