# PRIVATE-V1-ONE-COMMAND-001G engineering acceptance

Totals confidence scaling is produced with exact `Decimal` arithmetic at the public twelve-place
scale. Each OVER/UNDER pair sums exactly to its unchanged grade weight for A, B, C and D; canonical
JSON round-trips through `CurrentMarketConstraintBundle`; semantic hashes remain stable; and no
target, uncertainty, confidence cap or score-model mathematics changes.

The already-fetched official bootstrap is the sole source of a transient, raw-payload-hash-bound
current penalty hierarchy. Published positive integer order is an ordinal team hierarchy only.
Absent, null and zero roles are ignored; invalid types, negative values, duplicate team order,
non-contiguous order and player/team mapping conflicts fail closed. No body, credential or extra
request is retained or introduced.

Every private Stage-9 fixture request receives only its exact canonical player/team hierarchy.
For scored and unconverted penalty events, the eligible on-pitch player with the lowest published
order is selected deterministically. If none is on pitch, the existing positive governed donor
share is used and disclosed; if neither exists, `NO_ELIGIBLE_PENALTY_TAKER` remains. The hierarchy
changes sealed execution identity and is reported as
`CURRENT_FPL_PENALTY_HIERARCHY_DETERMINISTIC_V1`; actual donor use is reported as
`HISTORICAL_PENALTY_ROLE_FALLBACK_USED`.

Acceptance requires focused and affected markets, ingestion, FPL-points, private-v1 and optimiser
boundary regressions; changed-module branch coverage; Ruff; strict mypy; frozen sync; build and
installed-wheel smoke; repository and secret validation; and a safe literal one-command retry when
existing credentials are present. The retry must stop at and report the exact next blocker rather
than expanding scope.
