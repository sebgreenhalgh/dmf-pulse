# PRIVATE-V1-ONE-COMMAND-001K engineering acceptance

The automatic private policy preserves the complete official-FPL selectable non-squad universe,
then derives its maximum current transfer count from authenticated manager free transfers,
compiled transfer rules, the available incoming universe and the governed two-transfer STANDARD
limit. For the observed two-free-transfer state, 0, 1 and 2 transfers are all considered and none
incurs a hit. A third transfer is outside the declared private scope.

The deadline path applies certified pointwise dominance only within identical club, position and
appearance cohorts, then uses the explicitly labelled
`PRIVATE_CURRENT_TRANSFER_CANDIDATE_PRUNING_V1` expected/upside/value heuristic. Metric-boundary
ties are retained and an oversized tie set fails closed. Current squad members are never pruned.
Every legal action within the retained incoming-player scope is enumerated and receives exact
Stage-10 tactical treatment under the existing joint scenarios.

Exact action generation constructs position-compatible incoming combinations directly and applies
purchasability, affordability, club-quota, duplicate and current-ownership legality before Stage
10. The position-native generator must produce the same legal signatures as the prior exhaustive
toy oracle. A per-root squad cache ensures an identical resulting 15-player squad is evaluated at
most once.

Before optimisation, STDERR reports free transfers, transfer counts, full and retained incoming
counts, one- and two-transfer action counts, and unique exact tactical squad counts. The human
report states “exact tactical optimum within the declared bounded transfer candidate set”, names
the heuristic when used, and retains `ONE_GAMEWEEK_ZERO_TERMINAL_VALUE_OBJECTIVE`; it must not
claim a global FPL transfer optimum.

Acceptance also requires affected unit/property/contract/golden suites, branch coverage, Ruff,
strict mypy, frozen sync, build, clean installed-wheel verification, repository and secret
validation, exact-final-SHA CI, and the literal GW3 retry when existing runtime inputs are present.
